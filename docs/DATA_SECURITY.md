# 数据与安全

## 已清理内容

此发布副本不复制源项目的 `data/` 目录，也移除了会在首次启动时写回业务数据的源码种子。以下内容均不在发布副本中：

- 用户、账号、密码凭据、会话和验证码记录；
- 品牌、产品、SOP、知识正文和分类历史；
- 项目链接、个人待办、组织待办和用户偏好；
- 审计记录、版本快照、回收站记录；
- 附件、附件版本、内联图片及其索引；
- 原有行业术语和业务模板；
- 真实 `.env`、密钥、构建产物和 Git worktree 指针。

保留下来的是产品代码、数据库结构、迁移、测试和空白初始化逻辑。

## 发布前检查

```bash
pnpm release:check
```

此外还应人工检查：

```bash
git status --short
git ls-files
git grep -n -I -E "(password|secret|token|api[_-]?key|BEGIN .*PRIVATE KEY)"
```

命中结果不一定是密钥，例如变量名和文档示例也会匹配；必须逐项判断。不要把检查结果直接发布到公开 issue 或日志。

## 运行数据边界

SQLite 使用 WAL 模式。在线备份请使用项目脚本；手工复制数据库时先停止服务，并同时考虑主数据库、WAL、SHM 与附件目录。

附件是独立文件，数据库只保存元数据和引用关系。完整备份必须同时包含数据库与附件，恢复后应验证引用文件数量。

## 密钥与访问控制

- 每个正式环境使用独立的 `BETTER_AUTH_SECRET`。
- 不在源码、镜像、聊天记录或截图中保存真实密钥。
- 数据目录和备份目录只授权给服务账号与备份管理员。
- 通过 HTTPS 提供登录和附件访问。
- 定期复核管理员数量、成员状态和品牌/产品授权范围。
